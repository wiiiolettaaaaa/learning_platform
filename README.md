# Платформа персоналізованого навчання

Бакалаврська робота (КПІ, ІМ-31): «Інтелектуальна платформа персоналізованого навчання на основі аналізу знань та навчальної активності користувача».

Платформа оцінює рівень знань студента за його відповідями, вибудовує навчальну траєкторію за графом залежностей між темами й пояснює, чому рекомендує саме цю тему. Викладач бачить стан студентів і складні теми.

## Можливості
- **Модель знань (BKT):** ймовірність засвоєння кожної теми оновлюється після кожної відповіді.
- **Граф знань:** нова тема рекомендується, лише коли засвоєно її передумови.
- **Рекомендації з поясненнями:** нова тема або повторення забутої (враховується забування з часом).
- **Аналіз активності та ML-модель ризику відсіву:** логістична регресія за ознаками активності (дні без спроб, серія помилок, спроби за тиждень, середнє засвоєння); без файлу моделі працює простий індикатор за правилами.
- **Веб-інтерфейс студента:** навчання (питання, перевірка відповіді) і профіль знань.
- **Кабінет викладача:** таблиця студентів із ризиком відсіву та зведення за темами.

## Запуск (macOS)

### Бекенд
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload     # API: http://127.0.0.1:8000/docs
```

### Фронтенд (потрібен Node.js: `brew install node`)
```bash
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

Бекенд і фронтенд запускаються в окремих терміналах. Бекенд потребує активованого `.venv`.

### Як користуватися
- Введіть будь-яке ім'я, щоб навчатися: система запропонує тему, а відповіді оновлять профіль.
- Введіть `teacher` (або `викладач`), щоб відкрити кабінет викладача.

### ML-модель ризику відсіву
Готові ваги лежать у `models/dropout_logreg.json`, тож для запуску API ML-бібліотеки не потрібні. Щоб перенавчити модель і побачити метрики (`models/metrics.json`):
```bash
pip install -r requirements-ml.txt
python -m ml.train
```
Навчальна вибірка **синтетична** (`ml/simulate.py`: імітація студентів, мітка «жодної спроби в наступні 14 днів»), тому метрики демонструють роботу конвеєра, а не точність на реальних студентах. Модель порівнюється з індикатором за правилами та градієнтним бустингом; окремо оцінюється «раннє попередження» (студенти, які ще активні).

### Тести
```bash
python -m unittest discover -s tests -t . -v
```

## API
| Метод | Шлях | Опис |
|-------|------|------|
| GET | `/topics` | Список тем із передумовами |
| GET | `/topics/{id}/question` | Випадкове питання теми (параметр `exclude` виключає питання) |
| POST | `/answers/check` | Перевірка відповіді (`user_id`, `topic_id`, `question_id`, `choice`) і оновлення моделі знань |
| POST | `/answers` | Пряме оновлення моделі за результатом (`user_id`, `topic_id`, `correct`) |
| GET | `/profile/{user_id}` | Засвоєння тем і ризик відсіву |
| GET | `/recommendation/{user_id}` | Наступна тема або повторення з поясненням |
| GET | `/teacher/students` | Студенти: засвоєння, активність, ризик відсіву |
| GET | `/teacher/topics` | Зведення за темами: спроби, частка правильних, середнє засвоєння |

Інтерактивна документація: http://127.0.0.1:8000/docs

## Структура
```
app/
  knowledge.py     BKT-модель знань
  graph.py         граф знань (теми й залежності)
  recommender.py   рекомендації та забування
  activity.py      статистика активності й індикатор ризику за правилами
  risk_model.py    ML-модель ризику відсіву (ваги з models/)
  teacher.py       зведення для кабінету викладача
  main.py          REST API (FastAPI)
data/
  sample_course.json   приклад курсу
  questions.json       питання до тем
ml/                    симуляція даних і навчання моделі (simulate.py, train.py)
models/                ваги моделі (dropout_logreg.json) і метрики (metrics.json)
frontend/              React + Vite (навчання, профіль, кабінет викладача)
tests/                 модульні тести
```

## Поточні обмеження
- Дані зберігаються в пам'яті й зникають після перезапуску бекенду.
- Вхід викладача умовний (ім'я `teacher`), ендпоінти `/teacher/*` не захищені.
- Один приклад курсу (5 тем, по 2 питання).
- ML-модель навчена на синтетичних даних; на реальних студентах її потрібно перенавчити.

## Плани
PostgreSQL замість пам'яті, автентифікація й ролі (JWT), більше курсів і питань, збір реальних логів і перенавчання моделі.
